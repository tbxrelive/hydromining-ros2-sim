## 使用方法

新终端进入当前工作区后：

```bash
source setup_env.sh
```

只读环境检查（一条命令）：

```bash
./scripts/check_environment.sh
```

重复恢复依赖、构建与运行算法测试：

```bash
./scripts/setup_new_machine.sh
```

此恢复脚本面向已经装好 ROS 2 Jazzy/Gazebo Harmonic 的 Ubuntu 24.04 系统，不负责从空白操作系统安装 ROS。脚本遇到依赖、构建、导入或测试失败即非零退出。

`requirements.txt` 锁定直接依赖；`requirements-local.lock.txt` 固定本次 pip 本地安装包，不包含所有系统 apt 包。它们不是跨操作系统的完全独立环境，迁移仍需匹配 Ubuntu/Python/ROS 版本。torch 必须先使用官方 CPU index 安装，再安装 requirements，避免误拉 CUDA 包。

## 发现与修复

1. **Matplotlib 命名空间冲突**：系统的 `matplotlib-3.6.3-nspkg.pth` 在启动时预加载系统 mpl_toolkits；虚拟环境装入 3.9.4 后，py4dgeo 导入旧 mplot3d 与新 matplotlib 不匹配。移除虚拟环境新版，统一使用系统 3.6.3，py4dgeo 与 mplot3d 实际导入通过。
2. **OBJ 接缝焊接失败**：默认 trimesh.merge_vertices 保留法向差异，原煤壁仍有 13440 顶点并被判开放；纯几何焊接后为 12800 顶点、闭合。`voxel_grid.py` 显式指定 `merge_norm=True, merge_tex=True`，保持 1e-7 m 精度及原闭合性拒绝策略，没有改网格资产或放宽校验。既有原煤壁保真测试原先失败，修复后通过。
3. **ros2 control 插件解释器不一致**：只解包 CLI 后，系统 ros2 可发现命令但 view_controller_chains 因 graphviz 不可见失败。为项目环境生成使用虚拟环境解释器的 ros2 启动器后，该子命令也可正常加载。
