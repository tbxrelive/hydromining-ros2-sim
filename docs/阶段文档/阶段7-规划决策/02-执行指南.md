### 步骤 2：真实 Gazebo 单工况测试

#### 2.1 启动测试脚本

```bash
python3 test_scripts/phase7_real_loop.py tri_r5 --verbose
```

**参数说明**：
- `tri_r5`：工况名（empty / single / pair / tri_r5 / ring_r6 / dense）
- `--verbose`：显示详细决策理由
- `--gui`：启动 Gazebo GUI（默认 headless）
- `--keep-open`：测试结束后保持 Gazebo 运行（用于 GUI 检查）

#### 2.2 测试流程

```
1. 启动 Gazebo（headless，~20 秒）
2. 生成煤壁模型（带预喷残差，~5 秒）
3. 初始观测（3 个基线视点，~30 秒）
4. 决策循环：
   - 评估煤壁状态
   - 选择动作（观测/喷射/收尾）
   - 执行动作
   - 更新状态
5. 收尾（achieved 判决）
6. 清理 Gazebo 进程
```

#### 2.3 中断与恢复

- **中断**：`Ctrl+C` → 自动清理 Gazebo 进程
- **重新运行**：直接重新执行脚本（无需手动清理）

#### 2.4 故障排查

| 问题 | 可能原因 | 解决方法 |
|-----|---------|---------|
| Gazebo 启动超时 | 资源不足 | 关闭其他应用，增加 `gz_timeout=60` |
| 传感器无数据 | 阶段 6 配置错误 | 运行 `./scripts/run_phase6_acceptance.sh` 验证 |
| IK 求解失败 | 目标位置超出工作空间 | 检查 `spray_pose.py` 的 `workspace_limits` |
| 内存不足 | 多个 Gazebo 进程未清理 | `pkill -9 gz_sim; pkill -9 ruby` |

### 步骤 3：批量测试所有工况

#### 3.1 自动化脚本

创建批量测试脚本 `scripts/run_phase7_batch.sh`：

```bash
#!/bin/bash
set -e

cd ~/SCI/hydromining_ws
source .venv_stage4/bin/activate
source install/setup.bash

SCENARIOS="empty single pair tri_r5 ring_r6 dense"
TIMESTAMP=$(date +%Y%m%d_%H%M%S)
RESULTS_DIR="results/phase7/batch_${TIMESTAMP}"

mkdir -p "$RESULTS_DIR"

for scenario in $SCENARIOS; do
    echo "========================================="
    echo "测试工况: $scenario"
    echo "========================================="
    
    python3 test_scripts/phase7_real_loop.py "$scenario" \
        2>&1 | tee "$RESULTS_DIR/${scenario}.log"
    
    # 检查退出码
    if [ ${PIPESTATUS[0]} -eq 0 ]; then
        echo "✅ $scenario PASSED"
    else
        echo "❌ $scenario FAILED"
    fi
    
    # 等待资源释放
    sleep 5
done

# 生成总结报告
python3 - <<EOF
import json, glob
results = {}
for log in glob.glob("$RESULTS_DIR/*.log"):
    scenario = log.split('/')[-1].replace('.log', '')
    with open(log.replace('.log', '.json') + '/summary.json') as f:
        results[scenario] = json.load(f)

print("\n=== 批量测试总结 ===")
for s, r in results.items():
    print(f"{s:12s}: {r['verdict']:20s} 用时 {r['steps']} 步")
EOF
```

运行：
```bash
chmod +x scripts/run_phase7_batch.sh
./scripts/run_phase7_batch.sh
```

#### 5.2 手动观察要点

在 Gazebo GUI 中检查：

1. **初始煤壁**：
   - 是否有明显凹凸（预喷残差）
   - 颜色与纹理是否正常

2. **机械臂运动**：
   - 移动到观测位姿（3 个基线视点）
   - 轨迹是否平滑、无碰撞

3. **喷射过程**：
   - 水柱是否从喷嘴发出（TCP 正确）
   - 喷射位置是否对准缺口
   - 粒子效果是否显示（阶段 5）

4. **煤壁更新**：
   - 喷射后煤壁是否出现新凹坑
   - 凹坑位置是否与喷射位置一致
   - 凹坑深度是否合理（~5-7cm）

5. **任务收尾**：
   - 最终判决是否为 `achieved`
   - 煤壁表面是否平整（残差 ≤ 10mm）

## 🛠️ 常见问题与解决

### Q1: Gazebo 启动后传感器无数据

**症状**：
```
ERROR: No point cloud received within 30.0 seconds
```

**诊断**：
```bash
# 检查 Gazebo 是否运行
gz topic -l | grep /hydromining

# 检查 ROS 2 bridge
ros2 topic list | grep /hydromining/camera
ros2 topic hz /hydromining/camera/depth/points
```

**解决**：
1. 检查阶段 6 是否正常：`./scripts/run_phase6_acceptance.sh`
2. 确认 `ros_gz_bridge` 节点正常：`ros2 node list | grep bridge`
3. 查看 Gazebo 日志：`gz log -v 4`

---

### Q2: IK 求解频繁失败

**症状**：
```
WARNING: IK solve failed for target (0.12, 0.08), retry 3/5
```

**原因**：目标位置超出机械臂工作空间。

**解决**：
```python
# 检查 algorithms/planning/spray_pose.py 的配置
WORKSPACE_LIMITS = {
    'u': (-0.10, 0.10),  # 煤壁 u 方向（m）
    'v': (-0.10, 0.10),  # 煤壁 v 方向（m）
    'distance': (0.5, 0.8),  # 喷射距离（m）
}
```

修改策略：
1. 缩小搜索范围：限制在 ±8cm
2. 增加重试次数：`max_retries=10`
3. 降级到规则网格：固定 5×5 候选点

---

### Q3: DDPG 训练不收敛

**症状**：评估奖励持续为负，达成率 0%。

**诊断**：
```python
# 查看奖励分布
import numpy as np
data = np.load('results/phase7/ddpg_l1_spray/evaluations.npz')
print("Mean rewards:", data['results'].mean(axis=1))
print("Std rewards:", data['results'].std(axis=1))
```

**可能原因**：
1. **奖励尺度不当**：进度奖励太小，被惩罚淹没
2. **探索不足**：噪声过小，陷入局部最优
3. **训练不足**：15k 步可能不够（baseline 需 50k+）

**解决**：
1. 调整奖励权重：`progress_weight=5.0`（原 1.0）
2. 增大探索噪声：`sigma=0.2`（原 0.1）
3. 延长训练：`--total-timesteps 50000`

---

### Q4: 内存不足（OOM）

**症状**：
```
Killed (signal 9)
```

**诊断**：
```bash
# 查看峰值内存
cat results/phase7/real_*/resources.jsonl | grep -oP '"rss":\d+' | \
    awk -F: '{print $2}' | sort -n | tail -1
```

**限制**：
- 阶段 4-6 内存保护：3072 MB
- 真实 Gazebo + 感知：峰值 ~2.1 GB（安全）

**解决**：
1. 关闭 GUI：不加 `--gui`
2. 减少并行进程：一次只跑一个工况
3. 清理残留进程：`pkill -9 gz_sim; pkill -9 ruby`
