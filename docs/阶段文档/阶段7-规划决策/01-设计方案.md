## 📋 目标与需求

### 核心目标

实现水力采煤机器人的**自主观测规划**和**自适应喷射决策**，完成从感知到执行的完整闭环：

1. **主动观测规划**：根据当前不确定性，智能选择下一个观测位姿（NBV）
2. **自适应喷射决策**：根据煤壁状态评估，决定喷射位置、时长
3. **完整任务闭环**：观测 → 评估 → 决策 → 执行 → 评估 → …直到任务完成

## 🧩 核心算法设计

### 1. NBV（下一最佳视点）算法

**目标**：在观测预算有限的情况下，选择**信息增益最大**的观测位姿。

#### 算法原理

**信息增益定义**：观测某视点后，**不确定性降低的期望**

```python
gain(v) = Σ (可见性掩码(v, cell) × σ改善预测(cell))
```

- **可见性掩码**：几何约束（视场、遮挡、距离）
- **σ改善预测**：基于多传感器融合的不确定性降低量

#### 实现细节

```python
# algorithms/planning/nbv.py

class NextBestView:
    def select_viewpoint(self, candidates, current_state):
        """选择信息增益最大的视点"""
        gains = []
        for view in candidates:
            # 1. 计算可见性掩码（相机 + LiDAR）
            mask = self._compute_visibility_mask(view, current_state)
            
            # 2. 预测观测后的不确定性降低
            sigma_improvement = self._predict_sigma_reduction(mask)
            
            # 3. 综合评分（可见性 × σ改善）
            gain = np.sum(mask * sigma_improvement)
            gains.append(gain)
        
        return candidates[np.argmax(gains)]
```

**关键改进**：
- ✅ 可见性 = **相机 ∪ LiDAR**（解决坑底被坑沿遮挡的问题）
- ✅ 考虑距离衰减和入射角（近距、正视效果更好）

#### 验证结果（替身环境）

| 场景 | 初始覆盖率 | 补看后覆盖率 | 选中视点 |
|-----|-----------|------------|---------|
| tri_r5 | 0.342 | 0.443 | 近距视点（front_0p6） |

**结论**：NBV 正确选择近距视点，覆盖率提升 **10 个百分点**。

### 2. 规则决策基线（RulePolicy）

**设计哲学**：基于专家知识的**可解释决策**，作为强化学习的对比基线。

#### 决策流程

```
初始观测（3 个基线视点）
    ↓
评估煤壁状态
    ↓
    ├─ achieved（下界 ≥ 0.9）        → 收尾
    ├─ insufficient_evidence           → 补看（NBV）
    │   • 覆盖率 < 要求                → 补看
    │   • 置信度不足                    → 补看
    │   • 补看预算耗尽                  → 转喷射
    └─ not_achieved                   → 喷射
        • 计算缺口图（required_depth + k·σ − δ）
        • 选择缺口最大位置
        • 时长 = f(缺口深度)
```

#### 核心参数

| 参数 | 值 | 说明 |
|-----|---|------|
| `required_lower` | 0.9 | 收尾判据（置信下界） |
| `coverage_target` | 0.99 | 目标覆盖率 |
| `observe_budget` | 5 | 每轮补看上限（对齐 `maximum_views=8 - 3基线`） |
| `min_spray_duration` | 5.0 s | 最小喷射时长 |
| `max_spray_duration` | 8.0 s | 最大喷射时长 |

#### 缺口图计算（关键修正）

**原错误定义**：
```python
gap = required_depth - observed_depth  # ❌ 漏喷置信带跨界单元
```

**修正后（与判决准则一致）**：
```python
gap = required_depth + k * sigma - observed_depth  # ✅ 保守估计
```

**为什么重要**：
- 原定义只看均值，忽略不确定性
- 修正后考虑置信下界，避免误判"已达标"单元

#### 喷射时长策略

```python
def compute_spray_duration(gap_depth):
    """根据缺口深度计算喷射时长"""
    # 线性映射：[0, 0.03m] → [5.0s, 8.0s]
    duration = 5.0 + (gap_depth / 0.03) * 3.0
    return np.clip(duration, 5.0, 8.0)
```

**物理依据**：
- 小缺口（~10mm）：短时喷射（~5s）
- 大缺口（~30mm）：长时喷射（~8s）

#### 可解释性输出

```json
{
  "step": 3,
  "type": "spray",
  "rationale": "缺口最大 24.8 mm，位于 [-0.095 0.005]，喷射 7.4 s",
  "assessment": {
    "status": "not_achieved",
    "coverage": 0.994,
    "fraction_lower": 0.325
  }
}
```

### 3. 替身环境（Surrogate World）

**目标**：为强化学习提供**快速、确定性**的训练环境。

#### 两级替身架构

| 级别 | 吞吐 | 保真度 | 用途 |
|-----|------|--------|------|
| **L1** | ~2 步/秒 | 中（无渲染） | 批量训练、超参数搜索 |
| **L2** | ~0.12 步/秒 | 高（全渲染） | 策略验证、最终评估 |

#### L1 快速替身

**关键简化**：
```python
# 不走全分辨率渲染/时序融合
def _l1_build_map(self, views):
    """快速构建高度图"""
    height_map = HeightMap(...)
    
    for view in views:
        # 1. 从 truth_heights 提取表面
        surface = self._extract_surface_at_view(view)
        
        # 2. 按传感器分别计算可见性
        cam_mask = self._l1_sensor_mask(view, 'camera')
        lidar_mask = self._l1_sensor_mask(view, 'lidar')
        visible = cam_mask | lidar_mask  # 并集
        
        # 3. 加噪声后融入（每视点 3 帧）
        for _ in range(L1_FRAMES_PER_VIEW):
            noisy = surface + noise
            height_map.accumulate(noisy, visible)
    
    return height_map
```

**关键修复**：
- ✅ `L1_FRAMES_PER_VIEW=3`：对齐真实管线，否则单视点永远达不到 `minimum_observations=2`
- ✅ 可见性并集（相机 ∪ LiDAR）：VLP-16 能看到深度相机被遮挡的坑底

**性能优化**：
```python
# 工况缓存（蚀除确定性 + 固定参考系）
class SurrogateWorld:
    _episode_cache = {}  # {工况名: (phi, 表面, 掩码)}
    
    def restore_episode(self, scenario):
        if scenario in self._episode_cache:
            self.phi, self.surface, self.mask = self._episode_cache[scenario]
            # 热 reset ~0.35s（原 10-30s）
```

#### L2 高保真替身

```python
# 走完整感知管线
def observe(self, view):
    # 1. 渲染 RGB-D + LiDAR（~0.06s）
    rgbd, lidar = self.renderer.render(view)
```

### 4. 强化学习（DDPG）

**目标**：学习**自适应喷射参数**（u, v, duration），超越规则基线。

#### 为什么选择 DDPG

| 特性 | DDPG | 其他算法 |
|-----|------|---------|
| **动作空间** | 连续（适合喷射参数） | PPO/SAC 也行，但 DDPG 更简单 |
| **样本效率** | 中等（off-policy） | PPO（on-policy）需要更多样本 |
| **实现复杂度** | 低（SB3 现成） | TD3 更稳定但稍复杂 |

#### 状态空间设计

```python
observation = {
    # 图层（25×25 网格）
    'height_map': (25, 25),        # 高度均值
    'uncertainty': (25, 25),       # 不确定性 σ
    'gap_map': (25, 25),           # 缺口图（保守估计）
    'erosion_map': (25, 25),       # 已蚀除深度
    
    # 标量特征
    'fraction_lower': float,       # 置信下界达标比例
    'coverage': float,             # 覆盖率
    'sprays_done': int,            # 已喷射次数
    'observations_done': int       # 已观测次数
}
```

**维度**：25×25×4 + 4 = 2504 维

#### 动作空间设计（v1：spray 模式）

```python
action = [u, v, duration]  # 3 维连续
# u, v ∈ [-0.1, 0.1] m（煤壁坐标）
# duration ∈ [5.0, 8.0] s
```

**为什么只做喷射**：
- ❌ full 模式（[模式, 视点, 喷射参数]）失效：混合动作空间梯度消失
- ✅ spray 模式聚焦**自适应喷射**核心需求：位置 + 时长优化

#### 奖励函数设计

```python
reward = progress_reward + efficiency_penalty + terminal_reward

# 1. 进度奖励（连续）
progress = Δfraction_lower + 0.5 * Δcoverage

# 2. 效率惩罚
efficiency = -0.1 * (每步成本)

# 3. 终局奖励
if 判决 == achieved and 真值 == achieved:
    terminal = +10.0  # 双达标
elif 判决 == achieved and 真值 != achieved:
    terminal = -10.0  # 虚报达标（误达）
else:
    # 按置信下界缺口比例罚
    terminal = -5.0 * (0.9 - fraction_lower) / 0.9
```

**关键修正**：
- ❌ 原设计：诚实报告未达标也给 +10 → 策略学会第 1 步直接收尾
- ✅ 修正：只有双达标才给正奖励，虚报达标重罚

#### 训练配置


### 2. 累积接口（accumulate 字段）

**问题**：阶段 6 感知会话每次 `observe()` 都创建新会话，无法多轮补看。

**解决**：
```python
# algorithms/perception/assess.py

def observe(self, view, accumulate=True):
    """观测并融合到当前会话"""
    if accumulate:
        # 并入当前轮次
        self._current_round.append(view)
    else:
        # 新建轮次（喷射后第一次观测）
        self._current_round = [view]
```

**约束**：
- 喷射后第一轮观测**必须** `accumulate=False`
- 同一轮补看**必须** `accumulate=True`

### 3. 决策层预算管理

**问题**：原规则层无补看计数，连看同一视点直接撞顶 `maximum_views=8`。

**解决**：
```python
# algorithms/planning/decision.py

class RulePolicy:
    def __init__(self, observe_budget=5):
        self.observe_budget = observe_budget  # 硬上限
        self.observed_views_ = set()          # 本轮已看视点
    
    def choose_action(self, state):
        if len(self.observed_views_) >= self.observe_budget:
            # 预算耗尽，转喷射
            return self._spray_action(state)
        
        # 选 NBV，掩码已看视点
        candidates = [v for v in all_views if v not in self.observed_views_]
        best_view = self.nbv.select(candidates)
        self.observed_views_.add(best_view)
        return ('observe', best_view)
```

## 🎯 设计权衡与决策

### 1. 为什么先做规则基线，再做 RL？

| 原因 | 说明 |
|-----|------|
| **可解释性** | 规则基线输出清晰理由（缺口位置、增益预测） |
| **快速验证** | 无需训练，直接验证架构正确性 |
| **对比基准** | RL 必须**显著超越**规则基线才有意义 |
| **风险控制** | 规则基线确保项目可交付，RL 是加分项 |

### 2. 为什么 DDPG 只做 spray 模式？

| 决策 | 理由 |
|-----|------|
| ❌ **full 模式失效** | 混合动作空间（离散+连续）梯度消失 |
| ✅ **spray 模式对齐需求** | "自适应喷射"核心是**参数优化**（位置+时长） |
| ✅ **模式/视点留规则层** | NBV 已经很好，无需 RL 重新学习 |
| 🔮 **未来扩展** | P-DQN / TD3 / SAC 可探索混合动作 |

### 3. 为什么需要两级替身？

| 级别 | 训练阶段 | 用途 |
|-----|---------|------|
| **L1** | 探索、超参数搜索 | 快速迭代（~2 步/s） |
| **L2** | 验证、最终评估 | 高保真对齐真实（0.12 步/s） |

**类比**：
- L1 = 草图（快速试错）
- L2 = 精细渲染（最终确认）
