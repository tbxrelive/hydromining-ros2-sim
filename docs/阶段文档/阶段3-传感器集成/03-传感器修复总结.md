## 一、问题根因

### 1.1 核心问题

**Bridge 话题映射错误**：ROS-Gazebo bridge 配置的话题名与 Gazebo 实际发布的话题名不匹配。

**具体表现**：
- LiDAR 数据正常（话题名匹配）
- 相机 RGB/深度数据无数据（话题名不匹配）

### 1.2 根因分析（systematic-debugging 流程）

**第 1 层：信息收集**
```bash
# Gazebo 内部话题检查
gz topic -l | grep hydromining
# 输出：/hydromining/camera/image (有数据)
#       /hydromining/camera/depth_image (有数据)

# ROS 2 话题检查
ros2 topic list | grep hydromining
# 输出：/hydromining/camera/color/image_raw (存在但无数据)
#       /hydromining/camera/depth/image_rect_raw (存在但无数据)
```

**第 2 层：对比验证**
- ✅ Gazebo 内部：`gz topic -e -t /hydromining/camera/image` 有数据
- ❌ ROS 2 端：`ros2 topic hz /hydromining/camera/color/image_raw` 超时无数据
- ✅ Bridge 节点运行正常，但话题名配置错误

**第 3 层：根因确认**

`rgbd_camera` 插件在 Gazebo Harmonic 中的话题命名规则：
```xml
<topic>hydromining/camera</topic>
```
实际发布的话题：
- `/hydromining/camera/image` — RGB 图像
- `/hydromining/camera/depth_image` — 深度图像
- `/hydromining/camera/camera_info` — 相机参数
- `/hydromining/camera/points` — 点云

而 bridge 配置错误地使用了 RealSense 风格的命名：
- `/hydromining/camera/color/image_raw` ❌
- `/hydromining/camera/depth/image_rect_raw` ❌

## 二、修复方案

### 2.1 Bridge 话题映射修复

**修改文件**：`src/hydromining_robot/launch/robot_simulation.launch.py`

**修改前**（错误）：
```python
ros_gz_bridge = Node(
    package='ros_gz_bridge',
    executable='parameter_bridge',
    arguments=[
        '/hydromining/camera/color/image_raw@sensor_msgs/msg/Image@gz.msgs.Image',
        '/hydromining/camera/depth/image_rect_raw@sensor_msgs/msg/Image@gz.msgs.Image',
        '/hydromining/camera/color/camera_info@sensor_msgs/msg/CameraInfo@gz.msgs.CameraInfo',
        '/hydromining/camera/depth/points@sensor_msgs/msg/PointCloud2@gz.msgs.PointCloudPacked',
        '/hydromining/lidar/points@sensor_msgs/msg/PointCloud2@gz.msgs.PointCloudPacked',
        '/clock@rosgraph_msgs/msg/Clock[gz.msgs.Clock'
    ],
    output='screen'
)
```

**修改后**（正确）：
```python
ros_gz_bridge = Node(
    package='ros_gz_bridge',
    executable='parameter_bridge',
    arguments=[
        # 使用 Gazebo 实际发布的话题名
        '/hydromining/camera/image@sensor_msgs/msg/Image@gz.msgs.Image',
        '/hydromining/camera/depth_image@sensor_msgs/msg/Image@gz.msgs.Image',
        '/hydromining/camera/camera_info@sensor_msgs/msg/CameraInfo@gz.msgs.CameraInfo',
        '/hydromining/camera/points@sensor_msgs/msg/PointCloud2@gz.msgs.PointCloudPacked',
        '/hydromining/lidar/points@sensor_msgs/msg/PointCloud2@gz.msgs.PointCloudPacked',
        '/clock@rosgraph_msgs/msg/Clock[gz.msgs.Clock'
    ],
    remappings=[
        # 使用 ROS 2 remapping 映射到标准命名
        ('/hydromining/camera/image', '/hydromining/camera/color/image_raw'),
        ('/hydromining/camera/depth_image', '/hydromining/camera/depth/image_rect_raw'),
        ('/hydromining/camera/camera_info', '/hydromining/camera/color/camera_info'),
        ('/hydromining/camera/points', '/hydromining/camera/depth/points'),
    ],
    output='screen'
)
```

### 2.2 添加 GUI 参数支持

**目的**：允许无 GUI 模式启动仿真，避免多次测试时 GUI 堆积。

**修改内容**：
```python
# 1. 添加参数声明
declare_gui = DeclareLaunchArgument(
    'gui',
    default_value='true',
    description='Start Gazebo GUI if true'
)

# 2. 获取参数值
gui = LaunchConfiguration('gui')

# 3. 根据参数选择 Gazebo 启动参数
gz_args_with_gui = PythonExpression([
    "'", '-r ', world_file, "' if '", gui, "' == 'true' else '", '-r -s ', world_file, "'"
])

# 4. 在 LaunchDescription 中添加
return LaunchDescription([
    declare_gui,  # 新增
    declare_world,
    # ...
])
```

**使用方法**：
```bash
# 有 GUI（默认）
ros2 launch hydromining_robot robot_simulation.launch.py

# 无 GUI（测试用）
ros2 launch hydromining_robot robot_simulation.launch.py gui:=false
```

## 四、经验总结

### 4.1 正确的调试流程（systematic-debugging）

1. **信息收集**：分别检查 Gazebo 内部和 ROS 2 端的话题
2. **对比验证**：确定问题在哪一层（传感器渲染 vs bridge vs 配置）
3. **根因分析**：对照源码/文档找到话题命名规则
4. **验证修复**：每层逐步验证，确保修复有效

### 4.2 调试技巧

**关键命令组合**：
```bash
# 1. 列出 Gazebo 内部话题
gz topic -l | grep <namespace>

# 2. 测试 Gazebo 内部话题数据
gz topic -e -t <topic_name> | head -5

# 3. 列出 ROS 2 话题
ros2 topic list | grep <namespace>

# 4. 测试 ROS 2 话题数据
ros2 topic echo <topic_name> --once | head -10

# 5. 检查 bridge 节点配置
ros2 node info /ros_gz_bridge
```

**诊断流程**：
1. Gazebo 内部有数据 + ROS 2 端无数据 → **Bridge 配置问题**
2. Gazebo 内部无数据 → **传感器配置或渲染问题**
3. ROS 2 话题存在但无发布者 → **Bridge 未启动或崩溃**

### 4.3 避免的误区

1. ❌ **先下结论再找证据**（如"显卡崩溃"）
2. ❌ **用"禁用"代替"定位"**（禁用传感器让仿真跑起来）
3. ❌ **没对照两端话题**（没用 `gz topic -l` 对比 bridge 配置）
4. ❌ **没按分层流程**（跳过配置层直接调试环境/驱动）
5. ✅ **遇到问题立即调用 `/systematic-debugging`**
