# 阶段五 GUI 内存保护中断与修复验证

## 问题与证据

用户 GUI 运行在重放准备阶段中止，`failure.json` 记录聚合 RSS 3081.238 MiB，超过 3072 MiB 的保护上限。已完成两次喷射与重置，未完成完整验收。退出日志中的 SIGINT/SIGTERM 是失败后的清理过程，不是证明操作系统 OOM 或 Gazebo 自发崩溃的证据。

在相同低分辨率配置下补充分进程资源记录，未优化的完整无 GUI 基线峰值为 2626.723 MiB，喷射计算节点最高约 1108 MiB。仅限制分配区并省去额外相机的中间版本完成完整流程及保持窗口后退出，但其记录不能替代最终版本验证。

RSS 为进程求和，可能重复计入共享页；不能单凭这个数值定性为内存泄漏。连续喷射后计算节点的匿名映射显著增大；限制分配区、固定大块内存映射/归还阈值是针对临时工作区保留的修复，不改变数值模型。

## 修改

- 只对一键验收进程树设置 glibc 分配参数，避免大临时数组因动态阈值被长期保留。3 GiB RSS / 1 GiB 可用内存保护保持不变。
- GUI 默认不加载额外旁观相机；无 GUI 默认保留截图相机。两种世界的煤壁、机器人、灯光与原有传感器一致；可显式选择 `--overview` / `--no-overview`。
- `resources.jsonl` 记录阶段、分进程 RSS 与可用内存；失败文件附最后快照。保持窗口期间继续保护。
- 功能检查结束写 `checks.json`；退出清理后写 `summary.json`。保持期间发生失败不会被误写为通过。保持前额外重放并保存 `06_final_view`，留下可供观察的凹坑。
- 增加停喷水雾消散后点云稳定性、首次及累计凹坑的真实点云断言。
- 补齐压力基准、各类粒子发射率与发射区域宽度配置；原生插件兼容 v1，并通过 v2 接收有界配置。默认参数及破煤公式不变。

## 验证范围

最终验收以无 GUI 运行 GUI 所用的无额外相机世界，并测试保持窗口后的 Ctrl+C。它能验证数值、传感器、配置和退出流程，不能证明 GUI 渲染进程的实际内存或人工视觉效果。GUI 重验仍由用户执行。

证据归档目录：`results/phase5_acceptance/2026-10-26/gui_memory_fix/`。
