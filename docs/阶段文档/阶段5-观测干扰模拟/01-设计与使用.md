# 阶段五：水射流显示、飞溅与观测干扰

## 基线与物理含义

用户于本会话决定阶段四先通过，并选择“Gazebo 粒子优先、实时效果与干扰”。阶段四的实验标定、独立碰撞接触验证等遗留项继续保留。阶段五不改变公式①—⑲，不把显示粒子速度、水柱半径或粉尘参数当成物理标定结果。

实现为：独立纯算法 `jet_effects.py` → ROS 生命周期喷射控制器 → jet_bridge（复用 ros_gz_bridge 开源库） → Gazebo `WaterJetEffects` 系统插件 → 原生 Ogre2 粒子与真实传感器输出。插件不生成水滴刚体。

## 开源参考

- Gazebo Harmonic 官方 ParticleEmitter：https://gazebosim.org/api/sim/8/particle_emitter.html
- 喷涂插件架构：https://github.com/topguns837/gz_sim_spray_painting_plugin （Apache-2.0）。借鉴喷嘴跟随、独立粒子对象及开关管理思路；本项目重新实现，不引入其 Docker/Humble/UR5/MoveIt 演示栈、喷涂贴片或固定 2 m/s 参数。
- DualSPHysics 的 `8_ImpingingJet` 与 SPlisHSPlasH 仅作未来离线流体研究参考，本阶段未安装、未接入。
- 材质纹理和渐扩网格由本项目程序生成，无在线 Fuel 依赖。详见 `src/hydromining_sim/models/water_jet/NOTICE.md`。

## 时序与事务

`IDLE → PREPARING → SPRAYING → UPDATING → SETTLING → IDLE`。

1. 检查动作，冻结本次位置、方向及显示参数；用当前煤壁表面进行首次命中查询。
2. PREPARING 仅准备候选破坏结果，不修改剩余煤体，不显示喷射。数值求解保留原有 30 秒墙钟预算与 600 步上限。
3. SPRAYING 使用 ROS 仿真时间计时，显示连续水柱及粒子。当前破煤接口仍是固定姿态的一次喷射，不提供机械臂边运动边切割的轨迹模型。
4. UPDATING 停止粒子发射、移除水柱，将候选网格更新到 Gazebo visual/collision 后提交算法状态。
5. 原有粒子自然消散，SETTLING 等待 2.7 秒仿真时间，最终返回服务结果。
6. 忙碌时拒绝第二次喷射。重置立即请求清除效果并取消未提交计算，再串行恢复初始煤壁；ERROR 清除效果并返回失败。
7. 插件在 1 秒仿真时间收不到心跳时停止发射；重置立即清除全部效果对象。显示粒子仅作几何近似，不具备与任意实体的逐粒子碰撞。Ctrl+C 仅清理测试自己启动的进程。
8. 煤壁更新以实际场景中的模型名与目标网格 URI 确认为准；RPC 超时先做只读核实，核实缺失才允许一次禁止自动重命名的创建重发。状态无法确认时停止后续喷射，成功重置后恢复，避免回执丢失时盲目回滚旧模型。详见 [04-煤壁创建超时与事务确认修复.md](04-煤壁创建超时与事务确认修复.md)。

## 几何和观测约定

- ROS 状态几何统一 world，喷射轴沿 TCP 的 +Z。实际出口为现有 tcp 沿喷射方向后退 0.05 m；不修改原 URDF 或阶段四动作定义。
- 粒子原生发射轴是 +X，效果插件显式旋转到射流方向或命中面外法向。
- 煤壁首次命中来自当前数值表面，不使用目标包围盒；本版未自动查询任意外部 Gazebo 障碍物，不宣称完整场景遮挡已验证。
- 水柱半径默认 0.008 m，末端渐扩到 1.6 倍。该显示参数独立于冲蚀核 b(P,s)。流动高光由原生运动水滴叠加在贴图水柱上，不解算真实射流速度场。
- 命中时在表面外侧生成飞溅、水雾；只有候选结果确有体积去除时才生成工程化粉尘。无命中时显示从 TCP 起算 2 m 的自由射流（含出口偏移为 2.05 m），不生成冲击粒子。
- 保留原 RGB、深度、RGB-D 点云、LiDAR 话题与坐标约定。粒子开启后这些话题是受干扰观测，不能称为干净真值。
- 配对比较在同一煤壁尚未更新的喷射前/中进行。停喷后的点云用于测凹坑，不能用其与喷前的差异直接估计噪声。

## 参数与资源

`enable_effects` 默认 false，保证阶段四默认兼容；开启时加载独立效果桥接。`effect_preset` 为 off/low/medium/high，对应 0/0.4/1/1.8；显示强度 `min(2, preset_scale * pressure_MPa / effect_reference_pressure_mpa)`，压力基准默认 20 MPa、允许 1–60 MPa。这是未标定的有界工程映射，不推断真实雾化规律。

`config/jet_effects.yaml` 提供 `jet_core`、`jet_mist`、`jet_splash`、`jet_dust` 和 `jet_radius`。`jet_{mist,splash,dust}_rate_scale` 为各类粒子的相对发射率，范围 [0,1]，不增加最大粒子预算。`jet_{mist,splash,dust}_spread` 为切平面内发射区域宽度，默认 0.24/0.10/0.20 m、允许 0.02–0.50 m；沿外法向的区域厚度始终不超过 0.04 m。预设、压力基准、开关、半径、发射率与范围可在空闲时通过参数 API 修改；运行中拒绝修改本次动作参数。

效果桥接 `jet_bridge` 复用官方 RosGzBridge 组件和消息转换器；显式处理信号，在 context 有效时先取消 Gazebo 订阅并释放桥接句柄。ROS 控制器在取消动作后排空线程池，再销毁 executor、节点和 context。验收程序信号处理只置位，在安全的 Python 调度边界退出，避免中断 pybind 消息转换。

最大强度下理论活跃粒子数量小于 1200（底层 Ogre 每发射器仍可能预留原生配额），最多四个粒子发射器；水柱只有一个低面数显示网格。测试限制两个 CPU 核、数值线程为 1、总 RSS 3 GiB、可用内存下限 1 GiB。RSS 为验收客户端及仿真进程树的保守求和，可能重复计入共享页，不等于独占物理内存。保护阈值未提高。

验收脚本仅对本次进程树设置 `MALLOC_ARENA_MAX=2`、`MALLOC_MMAP_THRESHOLD_=131072`、`MALLOC_TRIM_THRESHOLD_=131072`，限制分配区及大临时数组的保留；不修改系统配置或破煤算法。机制参考 [glibc 官方说明](https://sourceware.org/glibc/manual/latest/html_node/Memory-Allocation-Tunables.html)。

无 GUI 默认额外启用 2 Hz 480×320 总览相机，用于截图；GUI 默认使用相同煤壁/机器人几何且不带此额外相机的 `coal_wall_acceptance.sdf`。`--overview` / `--no-overview` 可显式选择。可用 `--no-overview` 在无 GUI 下验证 GUI 所用世界配置，但这不能代替窗口渲染和人工视觉验收。

软件模糊、噪声、丢点和离群点保留为后续按需补充项，当前未实现独立软件退化节点，避免与原生粒子重复叠加。

粒子贴图使用 Ogre2 透明材质所需的预乘 RGB，透明边界 RGB 必须归零；渐变色图同时控制粒子寿命内的淡出，避免白色方块边缘。资产生成入口为 `models/water_jet/generate_assets.py`。

## 接口

- `/spray_action`、`/reset_coal_wall`：保留原服务类型。
- `/spray/status`：新增 `hydromining_robot/msg/SprayStatus`，RELIABLE depth=10，包含 shot_id、state、仿真时间、压力、时长、出口、方向、命中点、法向与显示强度。elapsed 是自本次准备/喷射起点累计的仿真时间，PREPARING 与 SPRAYING 转换时重新计时。
- `/hydromining/jet/command`：内部 String → gz.msgs.StringMsg；v1 为 23 个空格分隔有限数值：`version, command_id, mode, source_xyz, direction_xyz, hit_xyz, normal_xyz, has_hit, strength, eroding, core, mist, splash, dust, radius`。mode=0 清除，1 发射，2 停止并消散。渲染插件不参与破煤计算。
- 当前控制器发送 v2：前 23 项结构相同，version=2，追加 `mist_rate_scale, splash_rate_scale, dust_rate_scale, mist_spread, splash_spread, dust_spread`，共 29 项；插件继续接受 v1 默认配置，非法长度/非有限值/越界配置拒绝执行。
- `/hydromining/jet/diagnostics`：服务端回执，依次为 command_id、active、draining、emitter_count、emission_rate、length、sim_time。它证明服务器接收和创建状态，不能替代真实传感器验收。
