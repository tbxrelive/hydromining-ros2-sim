# 阶段六离线环境退化数据验证报告

日期：2026-10-28。范围：补充 6.0 的可复现背景粉尘压力测试数据。
**不是 6.0 整体完成，不是阶段六感知验收，不是矿井物理验证。**

## 本轮实现

- `perception/environment.py`：不依赖 ROS，不读取真值；沿原始传感器射线叠加退化。
- `test_scripts/phase6_degrade.py`：原始数据只读，拒绝非空输出目录、与输入重叠的目录、原生噪声或粒子已开启的数据源。
- `src/hydromining_robot/config/phase6_environment.yaml`：4 档能见度与 2 档随机噪声的全因子表，种子 `20261028`，最小斜距 `0.1 m`。不是完整五因素 L16 正交试验。
- `test_scripts/audit_phase6_environment.py`：独立核查来源/派生文件哈希、元数据、标签、射线方向和工况完整性。
- 传感器 RNG 由种子、快照相对路径、传感器名称派生，不依赖处理顺序；工况间使用共同随机数，便于配对比较。重复运行的数组一致性已纳入测试。

相机输入是 Gazebo +X 轴向深度。消光按斜距计算，轴向 sigma 转成斜距 sigma 后施加噪声，再转回轴向深度。
LiDAR 只修改原始射线距离，不改变方向；原本无回波的射线不会凭空补点。
深度中的原始无效值规范为 NaN；无退化工况的有效深度和点坐标保持一致。

观测存入 `工况/observations/场景/快照.npz`，保留内参、各自时间戳、TF、关节角等原始字段。
评估标签单独存入 `工况/evaluation_labels/场景/快照.npz`，不能作为感知输入。
标签为有效表面回波、丢点、假回波、原始无效；“有效”只说明生成模型的来源类别，不表示已经通过感知可靠性筛选。

多视点数据的全视场“有效表面回波数 / 原始有效射线数”（噪声 scale=0）：

| 能见度 | 深度相机 | LiDAR |
|---|---|---|
| 洁净（无限远） | 100.000% | 100.000% |
| 8 m | 35.601% | 15.686% |
| 3 m | 7.650% | 5.639% |
| 1.5 m | 0.883% | 2.712% |

这些比例包含整个视场的不同物体、距离和射线，**不是煤壁作业区的覆盖率**；
也不代表真实矿井传感器保留率。随机噪声打开后，越过最小距离的回波会记为丢点，故保留率可能额外降低。
当前还没有重建或判决算法，不能据此报告表面重建误差、三分类正确率或误判安全指标。

## 来源与边界

- 每次派生运行保存输入快照、真值归档文件、源记录 summary/provenance、算法和配置的 SHA256；真值文件仅用于来源登记，不参与观测退化计算。
- 首批 40 快照录制时没有启动来源文件：派生 manifest 明确记 `source_start_provenance_available=false`。当前哈希不能补证首批录制时冻结版本。多帧序列有原始 provenance。
- 原始真值不重复复制，manifest 指向项目内原始归档并记录哈希；迁移资料时需要同时保留原始归档。
- `noise_scale=1` 沿用未标定工程 sigma；不是新增实测标定，也未表示系统偏差或多帧相关误差。
- `dim_dust_*` 沿用预设名称，**本工具没有改变世界照明、RGB 或 Gazebo 原生粒子**。
- 本轮没有修改阶段四/五实现，也没有重跑其完整 Gazebo 端到端验收；2026-10-27 的完整回归仍为既有基线，不算本轮新实测。
- 没有新建 ROS 节点或接口，节点/Action 端到端验收不适用；GUI、world fog 传感器效果、昏暗/粒子联合实验和真实矿井效果尚未验证。

## 复现

在工作区中运行，输出路径必须新建或为空：

```bash
.venv_stage4/bin/python test_scripts/phase6_degrade.py \
  --source results/phase6/6.0/clean_dataset \
  --output /tmp/phase6_environment_new

.venv_stage4/bin/python test_scripts/audit_phase6_environment.py \
  --dataset /tmp/phase6_environment_new \
  --output /tmp/phase6_environment_new_audit.json
```

多帧数据将 source 换成 `results/phase6/6.0/sequence_clean`。
归档内 `multiview_audit_final.json` 是最终审计器结果；较早的 `multiview_audit.json` 保留为过程证据。
`sequence_audit.json`、`unit_final.log`、`build.log`、`syntax.log`、`installed_import.log` 和资源日志保留本轮实测。
