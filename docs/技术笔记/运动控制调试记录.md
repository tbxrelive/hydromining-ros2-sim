**环境**：
- ROS 2 Jazzy
- Gazebo Harmonic
- ros2_control + gz_ros2_control 插件
- joint_trajectory_controller

## 🐛 根本原因

### 问题 1：时间戳转换错误
**原始代码**：
```python
time_acc += duration  # duration 是浮点数，如 3.0, 4.0
point.time_from_start = Duration(sec=int(time_acc), nanosec=0)
```

**问题**：
- `int(3.5)` → `3`，小数部分丢失
- `nanosec=0` 导致所有时间点的纳秒部分都为 0
- 累积时间不准确

**修复**：
```python
time_acc += duration
point.time_from_start = Duration(
    sec=int(time_acc), 
    nanosec=int((time_acc % 1.0) * 1e9)
)
```

### 问题 2：发布器未等待连接
**原始代码**：
```python
publisher.publish(msg)  # 立即发布
```

**问题**：
- ROS 2 DDS 需要时间建立发布器-订阅器连接
- 消息可能在订阅者连接前就发送了，导致丢失

**修复**：
```python
# 等待发布器连接到订阅者
time.sleep(0.5)
publisher.publish(msg)
```

## ✅ 最终解决方案

完整的修复代码：

```python
#!/usr/bin/env python3
import rclpy
from rclpy.node import Node
from rclpy.qos import QoSProfile, ReliabilityPolicy
from trajectory_msgs.msg import JointTrajectory, JointTrajectoryPoint
from builtin_interfaces.msg import Duration
import time

class MotionController(Node):
    def __init__(self):
        super().__init__('motion_controller')
        
        # 1. 使用 BEST_EFFORT QoS 匹配控制器
        qos = QoSProfile(reliability=ReliabilityPolicy.BEST_EFFORT, depth=10)
        
        self.publisher = self.create_publisher(
            JointTrajectory,
            '/panda_arm_controller/joint_trajectory',
            qos
        )
    
    def send_trajectory(self, positions_list, duration_list):
        trajectory = JointTrajectory()
        trajectory.joint_names = [
            'panda_joint1', 'panda_joint2', 'panda_joint3',
            'panda_joint4', 'panda_joint5', 'panda_joint6', 'panda_joint7'
        ]
        
        # 2. 正确累积时间戳
        time_acc = 0.0
        for positions, duration in zip(positions_list, duration_list):
            point = JointTrajectoryPoint()
            point.positions = positions
            point.velocities = [0.0] * 7  # 必须提供
            
            time_acc += duration
            point.time_from_start = Duration(
                sec=int(time_acc),
                nanosec=int((time_acc % 1.0) * 1e9)  # 保留小数部分
            )
            trajectory.points.append(point)
        
        # 3. 等待连接建立
        time.sleep(0.5)
        
        self.publisher.publish(trajectory)
        self.get_logger().info('✓ 轨迹已发送')
```

## 📋 关键要点总结

| 类别 | 要点 | 说明 |
|------|------|------|
| **QoS 配置** | 必须匹配控制器 | 使用 `ros2 topic info -v` 查看订阅者配置 |
| **时间戳** | 正确处理浮点数 | 秒和纳秒都要设置，避免 `int()` 丢失精度 |
| **消息字段** | velocities 必填 | 即使为 0 也要显式提供 |
| **连接等待** | sleep(0.5) | 确保 DDS 发现机制完成 |
| **调试方法** | 监控 joint_states | 实时检测微小变化，不要只用肉眼 |

## 💡 经验教训

1. **DDS 通信不是瞬时的**：发布器需要时间与订阅者建立连接
2. **QoS 必须精确匹配**：RELIABLE vs BEST_EFFORT 不兼容
3. **不要忽略浮点精度**：Duration 的纳秒字段很重要
4. **调试工具链**：
   - `ros2 topic info -v` 查看 QoS
   - `ros2 topic hz` 检测消息频率
   - 自定义监控脚本检测微小变化
